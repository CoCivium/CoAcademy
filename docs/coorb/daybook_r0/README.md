# CoOrb+/CoCopy+ Daybook R0 | Offline Canopy

**Scope:** Public-safe, fictional-seed, single-file offline user-interface canary. Not a shipped CoOrb operating system, X2 desktop takeover, screen saver or provider adapter.

Open `index.html` directly in a modern browser. Select **Glance / CoMap / CoTime / Evidence**; inspect an Orb lens; explicitly add one event, make a revision referring to a predecessor, and export JSON by button. The fictional three-event seed can be reset; no content is read from other sessions, apps, OS clipboard, microphone, camera or local files.

## What this tests

- One event source, four projection modes; the selected mode changes display, not original event identity.
- CoAckRAW / CoReWis semantics: original wording is preserved, revision and challenge are additional events, not replacements.
- CoCopy+: explicit manual entry, no passive keylogging; no network, persistent storage, cookies, service workers or background agents.
- CoNull+: zero authorized external effects, unknowns not silently promoted.
- CoAkimbo+: challenge lens and ability to inspect dissent, not automatic growth or scientific claims.
- Accessibility: real buttons, labels, keyboard focus, reduced-motion preference, responsive layout and plain-text relationships.
- Export is explicitly activated. The browser may deny clipboard access to a local file; use Download JSON instead.

## Limitations

No model calls, X2 mouse hook, CoBar installer, background wallpaper/screensaver, inter-process receiver, GitHub synchronization, independent adoption, privacy audit, network flow monitoring, optical measurement, ET or G_d findings. In-tab state is lost on close unless the user deliberately exports it. Demonstrative source links are followed only by intentional click. No personal/user-specific data are included.

## Test and integration

Run `python3 tests/test_daybook.py`. It performs structural checks, then opens a headless browser if Playwright/Chromium is installed. The browser canary verifies: event addition, predecessor preservation, modes, undo, reset with confirmation, no fetch/XMLHttpRequest/WebSocket/EventSource calls, no storage writes, and no runtime errors. Browser test is `HELD` when a supported browser is missing. This is a controlled fixture, not an independent human accessibility acceptance test.
